结论
================================================================================
1) 0x1084-0x1172 这一段机器码，就是 page_init() 在默认构建下的全部实体；六步语义
   （① va_pa_offset → ② DTB 区间 → ③ npage → ④ 描述符数组 → ⑤ 全部置 Reserved →
   ⑥ 只把“扣掉内核镜像与描述符数组之后的完整空闲页”交棒）在指令层面一一对得上，
   没有多余分支。
2) 编译器把 sizeof(struct Page) 折叠成 *5<<3，并把 PADDR / pa2page / panic 全部内联，
   说明这些判断在运行期是零开销的常数比较 —— 这也是 lab2 框架代码能放心把 PADDR
   写成宏的底气。
3) 反汇编里读到的最关键两个常量：
      PHYSICAL_MEMORY_OFFSET = 0xFFFFFFFF40000000（立即数构造，不查表）
      sizeof(struct Page)    = 40 B
   两者与报告 §二 的内存布局实测表、以及图 EV12 的 GDB 读数完全一致，属于同一条
   证据链的静态端与动态端。
4) 编译期常量核对（不用跑程序就能确认的物理事实）：
      DRAM_BASE / PGSIZE = 0x80000000 >> 12 = 0x80000 = nbase
      内存末端 0x88000000 >> 12          = 0x88000 = npage
      pages_num = npage - nbase          = 0x8000 = 32768 项
      描述符数组字节数 = 32768 × 40      = 1310720 B ≈ 1.25 MiB
   这三条与运行期打印（pages[] VA 0xffffffffc0207000、nr_free 31929）互相封闭。
