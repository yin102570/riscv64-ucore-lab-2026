## 1. 总体架构与关键契约

### 1.1 数据结构之间的边界

本实验有两个容易混淆的“现场”：

- `struct context`：**线程切换现场**，只保存 `ra`、`sp`、`s0` 到 `s11`。它服务于 `switch_to()`，利用 RISC-V 的被调用者保存寄存器约定，不保存所有调用者保存寄存器。
- `struct trapframe`：**陷入/返回现场**，保存完整通用寄存器、`status`、`epc`、`badvaddr`、`cause`。它服务于 `__alltraps`、`__trapret` 和新线程第一次进入内核代码的恢复链路。

二者不能混用。`switch_to()` 只应保存和恢复 `struct context` 中的寄存器；把 `trapframe` 的全部寄存器搬进 `context` 会增加无意义的切换开销，也会让第一次线程启动的栈布局变复杂。

`proc_struct` 内部的职责边界如下：

| 字段 | 在本实验中的职责 |
|---|---|
| `state` | `PROC_UNINIT -> PROC_RUNNABLE`；调度器只选择 `PROC_RUNNABLE` |
| `pid` | 由 `get_pid()` 分配；`idleproc` 固定为 0，`initproc` 为 1 |
| `runs` | 调度器累计运行次数；初始必须为 0 |
| `kstack` | 普通线程由 `setup_kstack()` 分配两页；`idleproc` 直接使用 `bootstack` |
| `need_resched` | 调度点标记；`proc_init()` 中 `idleproc` 置 1，`test_lab4_thread` 主动置 1 |
| `parent` | 新线程的父线程；测试要求 `initproc->parent == idleproc` |
| `mm` | 用户地址空间管理器；本章内核线程全部为 `NULL` |
| `context` | 调度切换现场；新线程的 `ra` 指向 `forkret`，`sp` 指向其 trapframe |
| `tf` | 新线程第一次恢复时使用的 trapframe；`idleproc` 为 `NULL` |
| `pgdir` | 页表根物理地址；内核线程共享启动期内核页表 |
| `list_link` / `hash_link` | 分别挂入 `proc_list` 与 PID 哈希表 |

### 1.2 新线程第一次运行的闭包

必须把下面这条链作为一个整体验证，而不能只分别看每个函数：

```text
do_fork
  -> copy_thread: context.ra = forkret, context.sp = tf
  -> proc_run: current = next, lsatp(next->pgdir), switch_to
  -> switch_to: 恢复 next->context.ra/sp 和 s0-s11
  -> forkret: forkrets(current->tf)
  -> __trapret: 从 trapframe 恢复完整现场
  -> kernel_thread_entry: a0 = s1; jalr s0
  -> 目标函数 fn(arg)
```

因此 `kernel_thread()` 构造的临时 trapframe 必须让 `epc` 指向 `kernel_thread_entry`，让 `s0` 保存函数指针，让 `s1` 保存参数；`copy_thread()` 再把 trapframe 复制到新线程自己的内核栈顶部。只要其中一处寄存器或栈位置错，表面现象通常不是“参数不对”，而是内核直接跑飞或跳到非法地址。

### 1.3 中断与并发边界

`schedule()` 的选择过程和 `proc_run()` 的“换 `current`、换页表、换上下文”必须处于同一个不允许被打断的区间。`local_intr_save()` / `local_intr_restore()` 不是普通锁，而是保存并恢复 `sstatus.SIE`：

- 进入临界区前 `SIE == 1`：关中断，离开时恢复为开中断；
- 进入前 `SIE == 0`：保持关中断，不能错误地把外层已经关闭的中断重新打开。

这也是 Challenge 1 的实现依据。任何在 `schedule()` 中临时关中断、却无条件 `intr_enable()` 的写法都应在评审中否决。

## 2. 三个功能模块的设计与验收

## 2.1 功能模块一：虚拟内存页操作

**负责人：殷佳仪（2410665）。静态评审：兰雨杉。运行验证：宋秋实。**

### 目标文件与接口

```text
kern/mm/pmm.c
int page_insert(pde_t *pgdir, struct Page *page, uintptr_t la, uint32_t perm);
void page_remove(pde_t *pgdir, uintptr_t la);
```

### `page_insert()` 的设计契约

1. 先用 `get_pte(pgdir, la, 1)` 找到或创建叶页表项。这里可能分配中间页表页；失败必须返回 `-E_NO_MEM`，不能留下半初始化状态。
2. 新权限由 `perm` 指定，最终页表项要通过 `pte_create(page2ppn(page), perm)` 建立；`pte_create()` 已经负责设置 `PTE_V`，不要把 `PTE_V` 重复拼进 `perm` 后造成语义混乱。
3. 如果原地址已经有效映射到**同一个** `Page`：只更新权限和页表项，不能先 `page_ref_dec()` 再 `page_ref_inc()`，否则引用计数可能瞬间归零并把仍在使用中的页释放。
4. 如果原地址映射到**另一个** `Page`：先撤销旧映射并减少旧页引用计数，再增加新页引用计数并写入新页表项。顺序要保证失败路径不会留下旧映射已删、新映射未建立的空洞。
5. 页表项写入后调用 `tlb_invalidate(pgdir, la)`。即使当前 `pgdir` 不是正在使用的页表，保留一次保守失效也比留下旧翻译安全；本实验不为了省一次 `sfence.vma` 引入额外分支复杂度。

### `page_remove()` 的设计契约

1. 用 `get_pte(pgdir, la, 0)` 查询；不存在有效映射时直接返回，必须幂等。官方测试会连续两次删除同一个地址。
2. 有映射时清空叶页表项，减少物理页引用计数；计数归零时调用 `free_page()`。
3. 本实验**不回收空的中间页表页**。`check_pgdir()` 在删除两个叶映射后仍断言二级页表页的引用计数为 1，说明当前骨架把页表页的生命周期交给更高层管理；若在 `page_remove()` 里顺手释放空 PT，会直接破坏这一语义。
4. 删除后调用 `tlb_invalidate(pgdir, la)`，保证下一次访问不会命中旧翻译。

### 本模块必须通过的边界

- 新建映射后 `get_pte(..., 0)` 可取到项，`pte2page(*ptep) == page`，引用计数为 1。
- 同一地址从 `p2` 改映射到 `p1` 后，`p2` 的引用计数归零，`p1` 增加 1，权限位完全按新 `perm` 更新。
- 同一物理页在同一地址重复插入时，空闲页数不变化，不能出现“先减后加”导致的假释放。
- 重复 `page_remove()` 不崩溃、不重复减引用计数。
- 两个不同虚拟地址映射到同一物理页时，引用计数为 2；分别删除后逐步归零。

## 2.2 功能模块二：进程创建与初始化

**负责人：宋秋实（2410749）。静态评审：殷佳仪；独立检查：兰雨杉。运行验证：宋秋实。**

### 目标文件与接口

```text
kern/process/proc.c
static struct proc_struct *alloc_proc(void);
void proc_init(void);
int kernel_thread(int (*fn)(void *), void *arg, uint32_t clone_flags);
int do_fork(uint32_t clone_flags, uintptr_t stack, struct trapframe *tf);
static void copy_thread(struct proc_struct *proc, uintptr_t esp, struct trapframe *tf);
static int copy_mm(uint32_t clone_flags, struct proc_struct *proc);
```

### 2.2.1 `alloc_proc()`：先得到一块可安全使用的空白 PCB

`kmalloc()` 成功后必须把 PCB 置为明确的初始状态，而不是依赖未定义内存：

- `state = PROC_UNINIT`、`pid = -1`、`runs = 0`、`need_resched = 0`；
- `parent = NULL`、`mm = NULL`、`tf = NULL`、`pgdir = boot_pgdir_pa`；
- `context` 清零，`flags = 0`，名字清空，`list_link` 与 `hash_link` 初始化；
- 内核栈字段先置 0，等待 `setup_kstack()` 分配。

`pgdir` 保存的是供 `satp` 使用的页表根物理地址；内核线程共享启动期内核页表，不能把内核虚拟地址误写进 `satp`。

### 2.2.2 `proc_init()`：把当前执行现场变成 idleproc，再创建 initproc

顺序必须是：

1. 初始化 `proc_list` 和 PID 哈希表；
2. 用 `alloc_proc()` 得到 `idleproc`，立即令 `current = idleproc`；
3. 给 `idleproc` 分配 PID 0，状态改为 `PROC_RUNNABLE`，内核栈指向 `bootstack`，`need_resched = 1`，命名为 `idle`；
4. 增加进程计数，调用 `kernel_thread(init_main, "Hello world!!", 0)` 创建 `initproc`；
5. 断言返回 PID 为 1，保存 `initproc`，并命名为 `init`。

这里有两个不能凭直觉改动的点：`idleproc` 不是 `fork` 出来的，它复用当前执行现场和 `bootstack`；`initproc` 是通过 `kernel_thread()` 间接走 `do_fork()` 创建的。官方测试会直接检查 `idleproc->kstack == (uintptr_t)bootstack`、`idleproc->tf == NULL`，以及 `initproc->context.ra != 0`、`context.sp != 0`。

### 2.2.3 `kernel_thread()`：把函数包装成第一次运行的 trapframe

在栈上准备临时 `struct trapframe`，清零后设置：

- `gpr.s0 = (uintptr_t)fn`：目标函数地址；
- `gpr.s1 = (uintptr_t)arg`：目标函数参数；
- `epc = (uintptr_t)kernel_thread_entry`：第一次恢复后进入内核线程入口；
- `status`：读取 `sstatus`，设置 `SSTATUS_SPP` 和 `SSTATUS_SPIE`，清除 `SSTATUS_SIE`，使返回时能按预定路径进入内核态并保持中断控制语义。

最后调用 `do_fork(clone_flags, 0, &tf)`。临时 trapframe 在 `kernel_thread()` 返回后会失效，所以真正供新线程使用的是 `copy_thread()` 复制到新内核栈上的那一份。

### 2.2.4 `do_fork()` 与 `copy_thread()`：资源组合与首次现场

`do_fork()` 按指导书规定的七步执行，并且每一步失败都要回收已取得的资源：

1. `alloc_proc()`；
2. `setup_kstack()`，失败释放 PCB；
3. `copy_mm()`，本章当前线程的 `mm` 为 `NULL`，接口仍要保留；
4. `copy_thread()`，把 trapframe 和 context 放到新线程自己的内核栈；
5. 分配 PID，挂入 `proc_list` 与 PID 哈希表；
6. `wakeup_proc()` 置为 `PROC_RUNNABLE`；
7. 返回 PID。

`copy_thread()` 的关键不是“复制一段内存”，而是建立两个现场：

- 在新内核栈顶部为 `proc->tf` 预留 trapframe 空间并复制输入 trapframe；子线程的 `tf->gpr.a0` 置 0，表达“从子线程返回 0”；
- `proc->context.ra = forkret`，`proc->context.sp = (uintptr_t)proc->tf`，让 `switch_to()` 第一次恢复时进入 `forkret`，再由 `forkrets()` 把 `sp` 指向该 trapframe 并跳到 `__trapret`。

`copy_mm()` 本章只承担接口占位作用：内核线程共享内核地址空间，`current->mm` 本来为 `NULL`，不能在这里虚构一个用户地址空间，也不能把 `clone_flags` 当作已经完成用户态 `fork`。

### 2.2.5 本模块的失败模式

- `alloc_proc()` 未初始化字段，后续 `proc_run()` 读到野指针；
- `setup_kstack()` 失败后没有 `kfree(proc)`，进程计数和哈希表被污染；
- 先挂链表后分配 PID，`get_pid()` 的查找基准错乱；
- `copy_thread()` 把 trapframe 放到内核栈底部或越过栈顶，第一次 `sret` 时栈溢出；
- `context.ra` 写成 `kernel_thread_entry` 而不是 `forkret`，跳过 trapframe 恢复；
- `kernel_thread()` 的 `s0/s1` 与 `kernel_thread_entry` 的约定相反，目标函数拿到错误参数；
- `do_fork()` 在 `wakeup_proc()` 之前就把进程挂入调度链表，调度器选中一个尚未完整的 PCB。

## 2.3 功能模块三：进程调度与上下文切换

**负责人：兰雨杉（2412090，负责 `switch.S`、`sched.c` 和 `proc.c` 的 function3 区域）。静态评审：殷佳仪。运行验证：宋秋实。**

### 目标文件与接口

```text
kern/process/switch.S      -> switch_to(struct context *from, struct context *to)
kern/schedule/sched.c      -> schedule(void)
kern/process/proc.c        -> cpu_idle(void), proc_run(struct proc_struct *proc)
```

### 2.3.1 `cpu_idle()`：唯一显式调度点

`cpu_idle()` 是本实验的 idle 执行流。它不负责选择线程，只做：

1. 如果 `current->need_resched` 为真，调用 `schedule()`；
2. 循环等待，不主动结束。

函数标记为 `noreturn`，不能写出会返回 `kern_init()` 的路径。将调度点放在 `cpu_idle()` 中，是为了让 `idleproc` 在初始化完成后主动让出 CPU，而不是在任意 C 语句之间被抢占。

### 2.3.2 `schedule()`：FIFO 选择与中断保护

`schedule()` 必须完成以下语义：

1. 进入临界区，清除 `current->need_resched`；
2. 如果 `current != idleproc`，从当前进程的 `list_link` 下一个位置开始扫描；如果 `current == idleproc`，从 `proc_list` 头部开始扫描，形成 Round-Robin 的起点语义；
3. 只选择 `state == PROC_RUNNABLE` 的线程；
4. 扫描一整圈仍没有候选时，退回 `idleproc`；
5. 候选不为当前线程时调用 `proc_run(next)`；
6. 离开临界区并恢复进入前的中断状态。

不能只扫描一次链表尾部就假定“没有线程”，也不能把 `PROC_SLEEPING` 或 `PROC_ZOMBIE` 当作可运行线程。官方调度测试会创建两个额外线程；如果起点或扫描边界错误，常见结果是只运行其中一个，或 `idleproc` 永远无法回到 `initproc`。

### 2.3.3 `proc_run()`：先换当前线程和页表，再换上下文

`proc_run(proc)` 在 `proc != current` 时执行：

1. 保存当前线程指针 `prev` 和目标线程指针 `next`；
2. 在中断保护下令 `current = next`；
3. 用 `lsatp(next->pgdir)` 切换页表根；
4. 调用 `switch_to(&prev->context, &next->context)`；
5. 恢复中断状态。

顺序不能颠倒：`switch_to()` 返回后，代码仍运行在“某个线程的栈”上；因此 `current` 和页表必须在切换前设置成目标线程的值。若先切上下文再改 `current`，被恢复的线程会看到错误的当前线程。

### 2.3.4 `switch_to()`：只保存和恢复被调用者保存寄存器

`struct context` 的布局是固定的 14 个字段，`switch.S` 必须严格按字节偏移读写：

```text
0    ra
8    sp
16   s0
24   s1
32   s2
...
104  s11
```

参数约定：`a0 = from`，`a1 = to`。实现只做两件事：把当前 `ra`、`sp`、`s0-s11` 写入 `from` 指向的 context；从 `to` 指向的 context 恢复这 14 个寄存器；最后 `ret` 返回到新线程的 `context.ra`（第一次为 `forkret`）。不要在这里做进程选择、状态修改或页表切换。

### 2.3.5 本模块必须通过的边界

- `switch_to(from, to)` 之后，`to` 的 `ra/sp/s0-s11` 与保存前一致；
- 第一次切换到新线程时，能到达 `forkret -> forkrets -> __trapret -> kernel_thread_entry -> fn(arg)`；
- 两个测试线程都至少运行一次，且 `initproc` 能在合适调度点继续执行；
- `schedule()` 在无候选时回到 `idleproc`，不会空指针解引用；
- 临界区不会因为嵌套调用 `proc_run()` 而把外层关掉的中断错误打开。

## 2.5 Challenge：两个问题，两种交付

### Challenge 1：`local_intr_save/restore` 如何实现开关中断

由兰雨杉起草，宋秋实提供 `sstatus`/临界区的运行证据，殷佳仪审阅并写入最终报告。答案必须说明：

- `__intr_save()` 读取 `sstatus.SIE`，如果原本开启才调用 `intr_disable()`，并把“原本是否开启”作为 `bool` 返回；
- `__intr_restore(flag)` 只在 `flag == true` 时重新 `intr_enable()`；
- 因此它保存的是**调用点的中断状态**，不是简单的“进来关、出去开”；嵌套时外层已经关中断，内层退出不能擅自打开；
- 它不是自旋锁，不解决 SMP 核间互斥；本实验只运行单核内核线程，不能把局部关中断说成多核同步。

### Challenge 2：分页模式与 `get_pte()` 的拆分问题

由殷佳仪起草，兰雨杉核对页表索引与 PTE 布局，宋秋实只负责提供必要的静态/运行证据。答案必须覆盖：

1. `sv32` 是二级页表、32 位虚拟地址、34 位物理地址；`sv39` 是三级、39 位虚拟地址、56 位物理地址；`sv48` 是四级、48 位虚拟地址、56 位物理地址。级别数增加的本质是虚拟地址位宽增加，而每一级的页表项/索引宽度和页大小保持同一套结构，所以 `get_pte()` 中会出现形式相似的多段“查索引、缺表则建表”的代码。
2. 当前骨架的 `mmu.h` 顶部注释仍写着 Sv32，但 `PDX1SHIFT = 30`、`PDX0SHIFT = 21`、`PTXSHIFT = 12` 以及 `get_pte()` 的两级中间表查找，实际呈现的是 39 位三级页表布局。报告要把这个材料不一致点写清楚，不能把旧注释当结论。
3. 把“查页表项”和“缺页表时分配”合并在一个函数里，优点是调用者少写重复遍历、映射建立集中；缺点是查询接口带副作用，错误路径和测试注入更难，`create` 参数使函数承担了两种语义。更清晰的设计是拆成 `walk_pte()`（只查找）和 `alloc_pte_table()`（只在遍历失败时建表），再由 `get_pte()` 或更高层组合。当前实验为保持骨架兼容，可以保留合并接口，但报告中要说明这是工程折中，不是唯一正确写法。

Challenge 不修改默认评分路径，不把答案代码塞进 `pmm.c` 或 `proc.c`；所有实验性验证必须放在临时目录或 `report/tests/`，不能影响 `make grade`。

## 5. Prompt、Spec 与报告的统一写法

### 5.1 每个模块的 spec 必须包含什么

最终报告要求说明每个练习的 `spec` 是怎么写的。我们的 spec 不写成泛泛的“实现页表插入”，而固定包含六项：

1. **函数签名与调用者**：在哪个文件、被谁调用、返回什么；
2. **前置条件**：页表是否已建立、`Page` 引用计数处于什么状态、线程是否在中断关闭区；
3. **后置条件**：页表项、引用计数、TLB、链表、状态位分别应达到什么状态；
4. **失败语义**：返回 `-E_NO_MEM` 还是静默返回，失败时如何回滚；
5. **不变量**：例如“同一页重复映射不能先减后加”“`page_remove()` 不回收空 PT”“调度器不选 sleeping/zombie”；
6. **验收证据**：对应哪条官方断言、哪份日志、哪段 GDB 输出。

### 5.2 Prompt 的写法

每个模块的 prompt 由代码所有者起草，评审人补充边界条件，宋秋实根据实际 bug 回填“反例”。Prompt 必须包含：

- 当前实验的版本约束（Lab4，骨架已给函数名，不要重写整个文件）；
- 精确的函数签名、目标文件和允许使用的既有接口；
- 必须保持的 `lab2/lab3/lab4` 注释和学号替换规则；
- 官方测试的断言摘要，而不是只说“通过测试”；
- 禁止项：不引入用户态 mm、不实现 swap、不改 `tools/test_lab4.*`、不改变 `struct context` 布局；
- 输出要求：先给 diff，再解释不变量和失败路径，最后列出待验证假设。

每份 prompt 对应 `report/prompts/module1.md`、`module2.md`、`module3.md` 保存，最终 `report.md` 只摘录关键设计，不把整段对话原样粘贴。

### 5.3 AI 生成 bug 的记录格式

每个实际出现的 bug 都按以下五行归档，禁止只写“改好了”：

```text
现象：在哪个测试、哪条日志、哪一行看到什么异常
根因：违反哪个不变量，而不是“写法不对”
修复：改了哪个函数、为什么这个改动能恢复不变量
回归：重跑了什么命令，哪份原始日志证明 PASS
反思：如果重做一次，prompt/spec 应该提前约束什么
```

报告中只选有代表性的 bug，不把每个拼写错误都写成“重大发现”。重点会放在页表引用计数、TLB、`status` 位、`switch_to` 偏移、调度起点和首次运行栈这几类真正影响系统行为的问题上。
