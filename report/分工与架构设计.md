### 3.1 一张图看完整闭环

```text

  └─ __trapret

```

### 3.2 本实验的 Trap 语义

在 RISC-V 中，Trap 是中断和异常的统称：

- **中断**是异步事件，`scause` 最高位为 1；本实验的代表是 S 模式时钟中断 `IRQ_S_TIMER = 5`。
- **异常**是同步事件，`scause` 最高位为 0；本实验的代表是断点 `CAUSE_BREAKPOINT = 3` 和非法指令 `CAUSE_ILLEGAL_INSTRUCTION = 2`。

进入 S 模式 Trap 时，硬件至少完成：

1. `sepc` 保存触发 Trap 的指令地址（异常）或被打断的指令地址（中断）；
2. `scause` 记录原因；
3. `sstatus.SPIE` 保存原来的 `SIE`；
4. `sstatus.SPP` 保存 Trap 前的特权级；
5. `sstatus.SIE` 清零，进入 Trap 处理期间关闭 S 模式中断；
6. `pc` 跳到 `stvec` 指向的 `__alltraps`。

本次实验只在 S 模式内部往返，因此 `sstatus.SPP` 为 1；`sret` 用 `sepc` 和 `sstatus` 返回。Challenge 1 才会显式把 `SPP` 改成 0 并进入 U 模式。

### 3.3 Trap frame 契约

| 17 | 136 | `a7` | x17 |
| 18 | 144 | `s2` | x18 |
| 19 | 152 | `s3` | x19 |
| 20 | 160 | `s4` | x20 |
| 21 | 168 | `s5` | x21 |

| 31 | 248 | `t6` | x31 |
| 32 | 256 | `status` | `sstatus` |
| 33 | 264 | `epc` | `sepc`，异常处理器会改它 |
| 34 | 272 | `badvaddr` | `sbadaddr` / `stval` |
| 35 | 280 | `cause` | `scause` |

三条不可破坏的契约：

1. `SAVE_ALL`、`RESTORE_ALL`、`struct trapframe` 的字段顺序必须严格一致；
2. `x2/sp` 必须最后恢复，因为前面还要拿它当基址访问 trapframe；
3. `x0` 是硬连线零，不能“恢复”成别的值。

### 3.4 为什么 `sp` 要特殊处理

`SAVE_ALL` 的第一步是：

```asm
csrw sscratch, sp
addi sp, sp, -36 * REGBYTES
```

它先把**原始 sp**暂存在 `sscratch`，再把栈向下扩出 36 个槽位。随后保存通用寄存器时跳过 x2，最后用：

```asm
csrrw s0, sscratch, x0
...
STORE s0, 2*REGBYTES(sp)
```

把原 sp 写回 trapframe 的槽位 2，同时把 `sscratch` 清零（为递归异常留下“这次来自内核态”的标记）。因此 `RESTORE_ALL` 不能像其他寄存器那样在中间恢复 `sp`；必须在所有以 `sp` 为基址的 LOAD 完成之后，最后执行：

```asm
LOAD sp, 2*REGBYTES(sp)
```

这也是 `test_lab3_context.S` 能检测出的最典型错误之一：如果 `sp` 提前改成用户/旧栈指针，后面的恢复会读到错误地址，甚至把内核栈写坏。

### 4.2 模块 A：`trapentry.S`

#### 设计目标

完成“进入内核”和“返回原执行流”的底层闭环：

```text
Trap 发生
  → SAVE_ALL 形成 trapframe
  → a0 = trapframe 地址
  → trap(tf) 处理
  → __trapret
  → RESTORE_ALL 恢复 trapframe
  → sret
```

#### `RESTORE_ALL` 的设计约束

1. 先读取槽位 32 的 `sstatus` 和槽位 33 的 `sepc`，写回 CSR；异常处理器对 `tf->epc` 的修改必须在这里生效。
2. 恢复 `ra`、`gp`、`tp`、`t0`~`t6`、`s0`~`s11`、`a0`~`a7` 等通用寄存器；不恢复 x0。
3. 最后恢复槽位 2 的 `sp`。
4. 不恢复 `badvaddr` / `cause` 这两个只读或仅用于诊断的字段；`sret` 不需要它们。
5. 不修改 `SAVE_ALL`、`__trapret`、`struct trapframe`、`trap()` 签名。
6. 只使用调用约定允许的临时寄存器作为中间变量；被用作中间变量的寄存器最终仍要从 trapframe 恢复。

#### `__alltraps` 的设计约束

1. 必须在 `SAVE_ALL` 之后把当前 `sp` 作为 `trap(struct trapframe *tf)` 的第一个参数放入 `a0`。
2. 用 `jal trap` 进入 C 函数；返回后进入 `__trapret`，`sp` 必须仍然指向本次 trapframe。
3. `__alltraps` 保持 `.align(2)` 四字节对齐，因为 `stvec` 的低两位用于 Direct/Vector 模式编码。
4. 不在汇编入口里做业务判断；分类处理留给 C 层。
5. 本次 Lab3 只处理内核态（S→S）Trap；不做 Lab5 才需要的 U/S 双向 `sscratch` 换栈逻辑，避免把问题混在一起。

### 4.3 模块 B：`trap.c`

#### `interrupt_handler()` 规格

输入：`struct trapframe *tf`，其中 `tf->cause` 是 `scause`。中断的 `scause` 最高位为 1，分类时先去掉最高位再比较。

必须实现的行为：

| 分支 | 输出/动作 | 关键约束 |
|---|---|---|
| `IRQ_S_TIMER` | 重设下一次时钟事件；`ticks++`；当 `ticks % TICK_NUM == 0` 时调用已有的 `print_ticks()` 输出 `100 ticks`；累计打印达到 `SHUTDOWN_AFTER` 时调用 `sbi_shutdown()` | **每次进入都必须重新装载**；不能只计数不重设 |
| `IRQ_S_SOFT` | 输出 `Supervisor software interrupt` | 与测试的精确字符串一致 |
| 其他中断 | 输出 `Unknown interrupt: cause <n>` | `n` 是去掉最高位后的数值；测试覆盖 `15` |

定时器分支建议保持三段式，便于后续 Lab6 插入调度节拍：

```c
case IRQ_S_TIMER:
    clock_set_next_event();          /* 1. 先续订下一次事件 */
    ticks++;                         /* 2. 记账 */
    if (ticks % TICK_NUM == 0) {     /* 3. 周期输出/关机 */
        print_ticks();
        if (ticks / TICK_NUM >= SHUTDOWN_AFTER) {
            sbi_shutdown();
        }
    }
    break;
```

`SHUTDOWN_AFTER` 在当前骨架中没有定义，需要补一个受控的默认值。我们暂定 **10 次 `100 ticks` 输出，即 1000 个 tick 后关机**：

- 官方测试只等到 `ticks >= 200`，10 次输出不会抢在测试打印 PASS 之前关机；
- 如果把它设成 2，200 tick 时可能正好关机，测试存在竞态，不能这么写；
- 若答辩或指导书给出别的阈值，再单独调整并在报告中写明依据。

#### `exception_handler()` 规格

| 异常 | 输出 | `tf->epc` 处理 |
|---|---|---|
| `CAUSE_ILLEGAL_INSTRUCTION` | `Illegal instruction at 0x...` | 按实际指令长度推进 |
| `CAUSE_BREAKPOINT` | `Breakpoint at 0x...` | 按实际指令长度推进 |
| 其他 | 调用 `print_trapframe(tf)` | 不擅自猜测恢复方式 |

指令长度判断不能写死 `+4`。本实验至少覆盖：

- 16 位压缩指令：低两位不为 `0b11`，`epc += 2`；
- 32 位指令：低两位为 `0b11`，`epc += 4`。

```c
static inline uintptr_t instruction_length(uintptr_t pc) {
    uint16_t half = *(volatile uint16_t *)pc;
    return (half & 0x3) == 0x3 ? 4 : 2;
}
```

测试中的 `.word 0x0000007b` 是 4 字节非法指令；断点测试可能被汇编成 2 字节的压缩 `ebreak`，因此必须动态判断。若以后遇到 48/64 位长指令，再按 RISC-V 编码扩展；本次不虚构未覆盖的情况。

#### 不允许改的东西

- `trap()`、`trap_dispatch()`、`idt_init()`、`print_trapframe()`、`print_regs()` 的现有实现；
- `kern/driver/clock.c` 里的时钟初始化；
- `tools/` 下的评分脚本和测试源码（除非确认是环境适配且记录原因）；
- `init.c` 中 `idt_init(); pmm_init(); idt_init(); clock_init(); intr_enable();` 的锚点顺序。`tools/inject.py` 依赖最后一条 `idt_init();`、`clock_init();`、`intr_enable();` 的位置插入测试。

### 4.5 Challenge 1：用户态/内核态切换演示

指导书只在 `init.c` 的注释里留下：

```c
// LAB3: CAHLLENGE 1 If you try to do it, uncomment lab3_switch_test()
// user/kernel mode switch test
// lab3_switch_test();
```

当前骨架没有该函数、没有测试文件，也没有正式的验收字符串。因此我们把 Challenge 1 定义成一个**独立、可证伪、默认关闭**的扩展，而不是把它塞进评分路径。

#### 目标

演示一次真实的 `S → U → S` 往返：

1. 内核在 S 模式准备 U 模式入口、用户栈和 `sstatus`；
2. 通过 `sret` 进入 U 模式执行一段极短的测试指令；
3. 用户态执行 `ecall`，S 模式 Trap 入口接管；
4. 处理器在异常处理器中把 `tf->status.SPP` 改回 1、`tf->epc` 指向内核恢复点、`tf->gpr.sp` 指向内核栈；
5. `RESTORE_ALL` + `sret` 回到 S 模式，打印“回到内核”的标记后关机。

#### 受控实现方案

- 新增 `kern/init/lab3_switch_test.c` 及其用户端汇编，**不要放在 `kern/test/`**：`tools/inject.py` 在评分前会检查 `kern/test` 不存在，提交里若已有该目录会直接拒绝注入。
- 使用编译宏 `LAB3_CHALLENGE_SWITCH` 控制是否编译/调用，默认 `make` 和 `make grade` 不受影响。
- 运行低地址别名映射：在 `entry.S` 的根页表项 `[2]` 上按宏决定是否附加 `PTE_U`；高半区项 `[511]` 保持内核专用。
- 用户栈和用户入口都使用“高地址符号减去 `PHYSICAL_MEMORY_OFFSET`”后的低地址别名；入口汇编只使用位置无关的 `li`/`ecall` 指令。
- 因为 Lab3 的 `SAVE_ALL` 是内核专用版本，Challenge 的 Trap frame 会落在用户栈上；我们在进入 U 模式前设置 `SSTATUS_SUM`，使 S 模式能写用户页。这是**演示级实现**，不声称具备进程隔离或通用 U/S 换栈能力；真正的双向 `sscratch` 换栈属于 Lab5。

#### Challenge 验收

```bash

make DEFS=-DLAB3_CHALLENGE_SWITCH
timeout 12 qemu-system-riscv64 -machine virt -nographic -bios default \
  -device loader,file=bin/ucore.img,addr=0x80200000
```

必须满足：

1. 默认 `make grade` 仍然 `100/100`；
2. Challenge 构建能编译、能启动，出现 S→U→S 的三个阶段标记；
3. 宋秋实统一执行 GDB 观察，确认 `sstatus.SPP` 从 1 变为 0、再变回 1，`sepc` 从内核入口变为用户低地址、再回到内核恢复点；
4. 不发生异常循环，不出现未处理的 `scause=8` 兜底输出；
5. 报告中明确写出这是“演示级 U/S 往返”，并引用真实日志，不夸大隔离性。

## 8. Prompt 与报告写作要求

### 8.1 每个模块的 `spec` 必须写什么

报告要求说明“每个练习的 spec 是怎么写的、prompt 是怎么写的”。我们的规范是：

1. **前置事实**：列出真实文件、真实结构体、真实偏移、真实宏名，不凭记忆；
2. **输入/输出契约**：函数签名、参数含义、返回值、调用者；
3. **不变量**：哪些代码不能改，哪些寄存器不能碰，哪些偏移必须一致；
4. **后置条件**：执行完后哪些内存/CSR/寄存器必须是什么；
5. **失败模式**：如果违反会看到什么现象（例如只触发一次时钟、异常循环）；
6. **验证命令**：编译、运行、`grep` 判据、GDB 观察点；
7. **边界**：明确本实验不处理 48/64 位长指令、不做用户态换栈等，避免把“未覆盖”伪装成“已实现”。

### 8.2 Prompt 的写法

### 8.3 实际遇到的 bug 与解决记录

下表既有实现前的预判，也有最终代码上真实踩到的坑；每一行都对应一次实际构建或运行，修复后都做了回归：

| 现象 | 根因 | 修复思路 |
|---|---|---|
| 编译报 `interrupt_handler` 隐式声明 | 函数尚未定义/声明 | 先在 `trap.c` 中按签名补函数体；不要改 `trap_dispatch` |
| 编译报 `free_list`/`nr_free` 未定义 | Lab2 Best-Fit 未移植 | 补 `free_area` 及四个管理函数 |
| 一执行 `sret` 就崩 | `sstatus`/`sepc` 偏移错，或 `sp` 提前恢复 | 对照 36 槽表；`sp` 最后恢复；GDB 看 CSR |
| 恢复后寄存器值不对 | `RESTORE_ALL` 漏寄存器或用了未恢复的临时寄存器 | 逐个核对 `SAVE_ALL` 写入的槽位；用上下文测试 |
| 只出现一次 `100 ticks` | 没调用 `clock_set_next_event()` | 在定时器分支最先续订下一次事件 |
| 异常后无限重复 | `tf->epc` 没推进 | 按 2/4 字节动态推进 |
| 断点测试跳到错误位置 | 把 `ebreak` 固定当 4 字节 | 用 `objdump` 看实际编码，按低两位判断 |
| 评分注入失败 | `init.c` 锚点被重排，或提交里已有 `kern/test` | 保持锚点原顺序；自建测试放别处 |
| QEMU 零输出/指令页错误 | QEMU 7.0 启动路径、低地址映射或 `-kernel` 差异 | 复现 Lab2 的映射修复；分别记录 `make qemu` 与 `make grade` 命令 |
| 新版 binutils 报 `unknown CSR sbadaddr` | `sbadaddr` 是旧工具链对 `stval` 的别名，新版已删除 | 在文件级加 `.equ sbadaddr, 0x143`，不修改 `SAVE_ALL` 原文，汇编结果与 `stval` 完全一致 |
| QEMU 7.0 下 OpenSBI 跳到 0，内核不执行 | `fw_dynamic` 不读取 `-device loader` 的内核入口 | 评分脚本改用 `-kernel bin/ucore.img`；OpenSBI 打印 `Domain0 Next Address : 0x80200000` |
| Challenge 返回 S 模式时 `scause=0xd` 循环 | `RESTORE_ALL` 先把 `tf->status` 写回 `sstatus`，提前清 `SUM` 后无法再读用户栈上的 trapframe | `SUM` 保持到恢复完成；naked 恢复桩先切内核栈，再 `csrc sstatus, SUM`，随后恢复 `satp` |

## 9. 知识点对照（报告素材）

| 本实验知识点 | OS 原理对应 | 含义/关系/差异 |
|---|---|---|
| `trapframe` 保存通用寄存器 | 上下文切换（context switch） | 本实验保存的是同一执行流的 Trap 现场；进程切换还要保存/恢复地址空间、调度状态等，范围更大 |
| `sstatus.SPP/SIE/SPIE` | 特权级与中断使能 | 硬件用 CSR 自动记录来源和中断状态；OS 通过 `sret` 完成返回 |
| `scause` 最高位 | 中断/异常分类 | 最高位 1 为异步中断，0 为同步异常；这是 RISC-V 的具体编码，不是所有架构都相同 |
| `sepc` 推进 | 异常返回/指令重启 | 异常处理后必须跳过触发指令；中断则通常保留原 `sepc`，差异由 Trap 类型决定 |
| `sbi_set_timer()` | 时钟中断/时间片 | OpenSBI 提供 M 模式定时器服务；OS 每次中断后续订下一次，形成周期节拍 |
| `ticks` | 系统时钟计数 | 本实验只做统计打印；后续调度器会用它更新时间片、触发抢占 |
| `print_trapframe()` | 内核调试/故障现场 | 本实验用作未知异常兜底；它不等于“恢复”，只是保留现场 |
| Challenge 的 U/S 往返 | 用户态/内核态切换 | 本实验是演示级路径；真正的系统调用、地址空间隔离和换栈在后续实验 |

OS 原理中重要、但本次实验没有完整对应的内容：

- 进程/线程的完整上下文切换与调度（Lab6）；
- 系统调用参数检查、用户指针校验、`copyin/copyout`（后续 Lab5）；
- 缺页异常、VMA、页表权限、页面替换（PPT 提到的内容，属于后续虚拟内存/换页实验）；
- 文件系统、设备驱动、I/O 完成中断的完整处理；
- 多核、中断亲和性、锁与并发；
- 更长的 RISC-V 指令编码（48/64 位）和完整的异常恢复策略。
