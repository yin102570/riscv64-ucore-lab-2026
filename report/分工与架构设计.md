## 1. 总体架构


### 1.1 用户请求进入内核

```text
user/libs/syscall.c
  -> 把系统调用号和参数放入 a0..a5
  -> ecall
  -> __alltraps / SAVE_ALL
  -> trap()
  -> exception_handler()
  -> syscall()
  -> sys_*()
  -> do_*()
  -> __trapret / RESTORE_ALL
  -> sret
```

核心不是“调用一个 C 函数”，而是两次特权级切换：`ecall` 把 CPU 从 U 态带到 S 态，`sret` 再按 `sstatus` 中的 `SPP/SPIE` 返回。任何一次寄存器保存、栈切换或 `epc` 更新错误，都会表现为返回地址错误、重复执行 `ecall`、页故障或直接跑飞。

### 1.2 第一个用户进程

```text
proc_init()
  -> alloc_proc() 建立 idleproc
  -> kernel_thread(init_main)
init_main()
  -> kernel_thread(user_main)
  -> do_wait(0, NULL)
user_main()
  -> KERNEL_EXECVE(exit)
kernel_execve()
  -> do_execve()
  -> load_icode()
  -> current->tf 形成用户态现场
  -> __trapret / sret
```

`do_execve()` 只负责“把程序装进当前进程”；`kernel_execve()` 还必须把执行流送到 `__trapret`，否则程序虽然已经装入内存，CPU 仍停留在 S 态。这是本模块最容易出现“看似成功、实际没跑起来”的地方。

### 1.3 进程复制

```text
sys_fork()
  -> do_fork()
  -> alloc_proc / setup_kstack
  -> copy_mm()
  -> dup_mmap()
  -> copy_range()
  -> copy_thread()
  -> 子进程第一次被调度
  -> switch_to -> forkret -> forkrets -> __trapret -> 用户入口
```

普通 `fork` 的语义是：子进程拥有独立的 `proc_struct`、内核栈、trapframe 和用户地址空间；子进程从 `fork()` 返回 0，父进程得到子进程 PID。内核线程创建复用同一条 `do_fork()` 主链，但通过 `CLONE_VM` 共享地址空间，并且不复制用户页。

### 1.4 退出、等待与回收

```text
用户 exit()
  -> sys_exit()
  -> do_exit()
  -> 释放用户 mm / 页表
  -> PROC_ZOMBIE + exit_code
  -> 唤醒等待的父进程
  -> schedule()

父进程 wait()
  -> sys_wait()
  -> do_wait()
  -> 找到僵尸子进程
  -> unhash_proc / remove_links
  -> put_kstack / kfree
```

退出进程不能释放自己的内核栈和 PCB，因为它还要靠这两者完成 `schedule()`；最终回收必须由父进程的 `do_wait()` 完成。这是 Lab5 进程树不变量的一部分。

### 1.5 COW 的位置

COW 是普通 `fork` 复制路径的扩展，不是默认路径的替代品。默认评分必须先保证“每页真实复制”的正确性，再在独立开关或独立函数中启用 COW。这样即使 COW 出问题，也不会把基础 `forktest` 一起拖垮。

## 2. 数据结构与不可破坏的契约

### 2.1 `struct context` 与 `struct trapframe`

| 结构 | 保存内容 | 使用场景 | 不能做什么 |
|---|---|---|---|
| `struct context` | `ra`、`sp`、`s0` 到 `s11` | `switch_to()` 的进程/线程切换 | 不能拿它代替完整中断现场；不要把 `a0..a7` 全塞进去 |
| `struct trapframe` | 36 个槽位：通用寄存器、`status`、`epc`、`badvaddr`、`cause` | `__alltraps` 保存现场、`__trapret` 恢复现场、新进程第一次返回用户态 | 不能只恢复一部分寄存器；不能在 `sp` 仍指向用户栈时执行内核 C 代码 |

`context` 是“调度器视角”的现场，`trapframe` 是“异常返回视角”的现场。二者混用会让第一次进程启动、`fork` 返回值和用户态返回同时出错。

### 2.2 `proc_struct` 的关键字段

| 字段 | 契约 |
|---|---|
| `state` | `PROC_UNINIT -> PROC_RUNNABLE -> PROC_SLEEPING / PROC_ZOMBIE`；调度器只运行 `PROC_RUNNABLE` |
| `parent` | 指向父进程；`do_exit()` 重挂孤儿时同步修改 |
| `cptr/yptr/optr` | 子进程链、兄弟链、父进程指针；`set_links()` 与 `remove_links()` 必须配对 |
| `wait_state` | 记录睡眠原因，常见为 `WT_CHILD`、`WT_INTERRUPTED` |
| `flags` | `PF_EXITING` 表示进程已进入退出流程 |
| `mm` | 用户地址空间；内核线程为 `NULL`，用户进程在 `load_icode()` 后建立 |
| `pgdir` | 页表根物理地址；`proc_run()` 用它切换 `satp` |
| `kstack` | 内核栈基址；由父进程在 `do_wait()` 中最终释放 |
| `tf` | 当前进程的 trapframe；`load_icode()` 和 `copy_thread()` 都会改写它 |

### 2.3 五条硬性不变量

1. **用户指针先检查再解引用。** `sys_wait()` 的 `code_store`、`sys_exec()` 的程序名和二进制、`do_execve()` 的 `name` 等，都必须经过 `user_mem_check()`；`write` 参数必须按写权限检查。
2. **`ecall` 的 `epc` 只前移一次。** 在 `exception_handler()` 识别 `CAUSE_USER_ECALL` 后执行 `tf->epc += 4`，不能既在异常入口又在 `syscall()` 中重复加。
3. **系统调用结果只写回 `tf->gpr.a0`。** 用户态只认这个返回寄存器；`syscall()` 不得直接把结果丢在某个临时 C 变量里。
4. **返回用户态时先恢复 `sstatus`/`sepc`，最后恢复用户 `sp`。** `sscratch` 必须保存下一次陷入可用的内核栈指针；`RESTORE_ALL` 不能继续沿用 Lab3 只适用于内核态的写法。
5. **僵尸进程只能由父进程 `do_wait()` 回收。** `do_exit()` 不调用 `put_kstack()`，也不 `kfree(current)`；否则当前进程在 `schedule()` 前后就会失去可执行栈。

## 3. 功能模块与实现边界

### 3.1 模块一：用户态系统调用

**负责人：殷佳仪。**

涉及文件与函数：

```text
kern/trap/trapentry.S        SAVE_ALL / RESTORE_ALL
kern/trap/trap.c             exception_handler()
kern/syscall/syscall.c       syscall()
                             sys_exit / sys_fork / sys_wait / sys_exec
                             sys_yield / sys_kill / sys_getpid
                             sys_putc / sys_pgdir
```

系统调用 ABI 固定为：`a0` 是调用号，`a1` 到 `a5` 是参数，返回值写回 `a0`。本实验使用的编号至少包括：

| 调用号 | 名称 | 内核落点 |
|---|---|---|
| 1 | `SYS_exit` | `do_exit()` |
| 2 | `SYS_fork` | `do_fork()` |
| 3 | `SYS_wait` | `do_wait()` |
| 4 | `SYS_exec` | `do_execve()` |
| 10 | `SYS_yield` | `do_yield()` |
| 12 | `SYS_kill` | `do_kill()` |
| 18 | `SYS_getpid` | `current->pid` |
| 30 | `SYS_putc` | `cputchar()` |
| 31 | `SYS_pgdir` | 打印当前页表信息 |

`exception_handler()` 只处理 `CAUSE_USER_ECALL` 这一分支：确认来源、把 `epc` 前移 4 字节、调用 `syscall()`；其他异常仍走原来的诊断/终止路径，不能吞掉。`syscall()` 必须检查调用号是否落在分发表范围内，非法编号应打印 trapframe 并 panic，不能越界取函数指针。

`sys_fork()` 不能自己重新拼一套进程复制逻辑，它只是把 `current->tf` 和 `current->tf->gpr.sp` 交给 `do_fork(0, stack, tf)`。`sys_exec()` 把程序名、长度和二进制指针转交 `do_execve()`；`sys_wait()` 的退出码指针必须在 `do_wait()` 内按写权限检查。

`RESTORE_ALL` 是本模块的汇编难点。进入异常时，从 U 态来的 `sp` 是用户栈，`sscratch` 保存内核栈；从 S 态来的 `sscratch` 应为 0。因此 `SAVE_ALL` 要交换 `sp` 与 `sscratch`，并在 `sp == 0` 时取回内核栈。返回时要把内核栈指针重新写回 `sscratch`，恢复 `sstatus`、`sepc` 和通用寄存器，最后恢复用户 `sp`，再执行 `sret`。这条约定不成立时，常见现象是第一次系统调用能进内核，但返回后用户程序立即页故障。

### 3.2 模块二：创建并加载第一个用户进程

**负责人：殷佳仪。**

涉及函数：

```text
kern/process/proc.c
  alloc_proc()
  kernel_thread()
  init_main()
  user_main()
  kernel_execve()
  do_execve()
  load_icode()
```

实现顺序必须是“先能创建内核线程，再能装入 ELF，最后才能返回用户态”，不能先写 `sret` 再补地址空间。

`alloc_proc()` 逐字段初始化：状态为 `PROC_UNINIT`，PID 为 `-1`，`runs = 0`，`need_resched = 0`，`parent = NULL`，`mm = NULL`，`tf = NULL`，`pgdir` 使用启动期内核页表，链表节点清空。不要用整块 `memset` 代替对链表节点和指针字段的明确初始化。

`kernel_thread()` 构造一个临时 trapframe，使 `epc` 指向 `kernel_thread_entry`，`s0` 保存函数地址，`s1` 保存参数，然后调用 `do_fork(clone_flags | CLONE_VM, 0, &tf)`。临时 trapframe 在函数返回后失效，真正被新线程使用的是 `copy_thread()` 复制到新内核栈顶的那一份。

`load_icode()` 负责完整的 ELF 装载：

1. 检查 `ELF_MAGIC`、`p_filesz <= p_memsz`，只处理 `ELF_PT_LOAD` 段；
2. `mm_create()`、`setup_pgdir()`，按 ELF 段权限建立 VMA；
3. 为代码段/数据段分配物理页，复制文件内容，BSS 部分清零；
4. 建立 `[USTACKTOP - USTACKSIZE, USTACKTOP)` 的用户栈 VMA，并预分配栈顶若干页；
5. 绑定 `current->mm`、`current->pgdir`，切换 `satp`；
6. 清空并设置当前 trapframe：`gpr.sp = USTACKTOP`、`epc = e_entry`，`status` 清除 `SSTATUS_SPP`、设置 `SSTATUS_SPIE`、清除 `SSTATUS_SIE`。

其中第 6 步是“能不能回到 U 态”的核心。只装好页表、不设置 trapframe，`sret` 会回到错误地址或错误特权级；只设置入口、不设置用户栈，用户程序的第一条函数调用就会踩坏地址。

`do_execve()` 的顺序不能颠倒：先检查并复制 `name`，再切回内核页表、递减旧 `mm` 引用计数并在计数为 0 时销毁旧地址空间，最后调用 `load_icode()`。程序名必须在销毁旧用户地址空间前复制到内核缓冲区，否则 `name` 会变成悬空用户指针。

`kernel_execve()` 采用“构造/复用当前 trapframe，然后跳到 `__trapret`”的清晰路径，而不是只调用 `do_execve()` 后返回。`do_execve()` 成功后，当前进程的 `tf` 已经被 `load_icode()` 改写成用户态入口；此时把 `sp` 指向该 trapframe 并跳转 `__trapret`，才能让 `sret` 真正进入 U 态。这个函数不应有“正常返回”的语义。

`init_main()` 先保存空闲页数和内核分配量，创建 `user_main`，再循环 `do_wait(0, NULL)` 等待所有用户进程退出。全部退出后检查 `initproc->cptr/yptr/optr` 为空、`nr_process == 2`，并输出内存检查结果。这个检查不是装饰，它验证进程树和资源回收是否真的闭合。

关于“用户程序何时被预先加载”：Lab5 的用户程序在构建阶段被链接进内核镜像，`user_main()` 通过 `_binary_obj___user_*_out_start/size` 之类的符号直接访问 ELF 字节；它不是运行时从文件系统读取的。ucore 本实验没有完整文件系统，也没有用户态加载器，所以采用预嵌入方式。这与常用操作系统“由 shell/加载器打开文件、映射可执行文件、再由内核建立用户映像”不同，但两者最终都要完成 ELF 解析、地址空间建立和入口跳转。

### 3.3 模块三：复制用户进程

**负责人：宋秋实。**

涉及函数：

```text
kern/process/proc.c   do_fork()  copy_mm()  copy_thread()
kern/mm/vmm.c         dup_mmap()
kern/mm/pmm.c         copy_range()
```

`do_fork()` 是进程复制的总装线：

```text
alloc_proc
  -> proc->parent = current
  -> setup_kstack
  -> copy_mm
  -> copy_thread
  -> get_pid / hash_proc / set_links
  -> wakeup_proc
  -> return child pid
```

失败路径必须逐级回收：内核栈分配失败释放 `proc`，`copy_mm` 失败释放内核栈，任何一步失败都不能把半初始化进程挂进全局链表或哈希表。`current->wait_state` 在创建子进程前要处于可控状态，避免父进程已经处于等待状态时被错误唤醒。

`copy_mm()` 区分 `CLONE_VM` 与普通复制。共享路径让子进程指向父进程的 `mm` 并增加引用计数；普通路径创建新 `mm`、建立新页表、调用 `dup_mmap()` 复制 VMA 和页。不能把“共享 mm”误写成“复制 mm 后再共享页”，这两条路径的引用计数和释放责任不同。

`dup_mmap()` 按父进程 VMA 逐段创建子 VMA，并保持区间顺序和权限。默认实现调用 `copy_range()` 做真实页复制；COW 只能作为独立分支，不能改变默认评分路径。

`copy_range()` 对 `[start, end)` 逐页处理：源 PTE 无效时按页表粒度跳过空洞；有效时在目标页表中取得/建立 PTE，分配新物理页，`memcpy(page2kva(src), page2kva(dst), PGSIZE)`，再用 `page_insert()` 建立映射。权限至少保留 `PTE_U` 以及源页的 `R/W/X` 语义；源页只读时不能因为复制就变成可写。

`copy_thread()` 把 trapframe 放到子进程内核栈顶，复制父进程的现场，把 `gpr.a0` 置 0，表示子进程从 `fork()` 返回 0；`context.ra = forkret`，`context.sp = proc->tf`。用户进程的 `gpr.sp` 使用 `sys_fork()` 传入的用户栈指针；内核线程的 `stack == 0`，使用新内核栈上的 trapframe。第一次被调度后走：

```text
switch_to -> forkret -> forkrets(tf) -> __trapret -> sret -> 用户程序
```

### 3.4 模块四：退出、让出、终止与等待

**负责人：兰雨杉。**

涉及函数：

```text
kern/process/proc.c
  do_exit()
  do_yield()
  do_kill()
  do_wait()
```

`do_exit()` 的禁止条件和顺序必须严格遵守：

1. `current == idleproc` 或 `current == initproc` 直接 panic；
2. 先切回内核页表，再递减 `mm` 引用；计数为 0 才执行 `exit_mmap()`、`put_pgdir()`、`mm_destroy()`；
3. 清空 `current->mm`，设置 `PROC_ZOMBIE` 和 `exit_code`；
4. 在关中断临界区内唤醒等待的父进程；
5. 把自己的孤儿子进程重挂到 `initproc` 下，并修正 `parent/cptr/yptr/optr`；
6. `local_intr_restore()` 后调用 `schedule()`，正常情况绝不返回。

`do_yield()` 只设置 `current->need_resched = 1` 并返回 0；它不直接调用调度器，也不改变进程状态。`do_kill()` 查找目标 PID，设置 `PF_EXITING`；若目标处于可中断等待，则唤醒它。找不到目标或目标已退出时，返回约定的错误码，不能误唤醒当前进程。

`do_wait()` 与 `do_exit()` 是一对：先检查 `code_store` 写权限，再按指定 PID 或任意子进程查找僵尸态；没有僵尸但仍有子进程时，把当前进程置为 `PROC_SLEEPING`、`wait_state = WT_CHILD` 后 `schedule()`；被唤醒后重新扫描。找到僵尸后，在关中断区间内 `unhash_proc()`、`remove_links()`，最后 `put_kstack()`、`kfree()` 并写回退出码。等待期间若当前进程被 `PF_EXITING` 标记，应转入 `do_exit(-E_KILLED)`。

### 3.5 COW Challenge

**负责人：兰雨杉。**

COW 的默认策略是“父进程 fork 后，可写用户页在父子双方都变为只读，并标记为 COW；任一方写入时触发 page fault，内核复制一页并恢复写权限”。默认 `copy_range()` 仍然保留真实复制，COW 通过独立函数/开关接入，避免影响基础 `forktest`。

建议状态机如下：

| 状态 | PTE 状态 | 引用计数 | 触发 | 迁移 |
|---|---|---|---|---|
| 私有可写 | `W=1, COW=0` | 1 | 进程私有页 | `fork` 时转为共享只读 |
| 共享只读 | `W=0, COW=1` | >1 | 父子共享 | 写 fault 时复制 |
| 写时复制中 | 旧页 `W=0, COW=1`；新页 `W=1, COW=0` | 旧页递减 | 写 fault 且引用计数 >1 | 分配新页、复制、更新 PTE、刷新 TLB |
| 独占只读 | `W=0, COW=1` | 1 | 另一方已退出 | 写 fault 时可原地恢复 `W=1`，不复制 |
| 已回收 | 无效 PTE | 0 | `exit_mmap` / 解映射 | 释放物理页 |

实现要点：

- 使用空闲的软件 PTE 位表示 COW，不能让硬件把它误判为有效写权限；具体位号以 `kern/mm/mmu.h` 为准。
- `cow_pgfault()` 只处理“VMA 可写 + 当前访问为写 + PTE 有效 + `COW=1` + `W=0`”的页故障；其他情况仍交给通用页故障处理。
- 复制时先分配新页，再复制旧页内容，再用 `page_insert()` 建立新 PTE；旧页引用计数递减，只有归零才释放。
- 修改 PTE 后必须 `tlb_invalidate()` 或等价刷新，否则 CPU 可能继续使用旧的只读翻译。
- 进程退出、`exec` 替换地址空间、`mm` 销毁时都要正确递减引用计数，不能把共享页重复释放。
- 测试至少覆盖：父子各写同一页、连续两次 fork、只读代码页、父进程先退出、子进程先退出、TLB 刷新后的再次写入。

Dirty COW 的讨论必须落在真实差异上。Linux 的 Dirty COW 是“私有文件映射的 COW 与写入竞态”导致的权限提升问题；ucore Lab5 的用户页是匿名页，没有文件映射、没有用户态缺页注入，也没有同等的多核竞态窗口。因此我们可以在受控测试路径中演示“错误地只提升写权限、不做私有复制”会造成父子互相可见，但不能声称在 ucore 中完整复现了 Linux Dirty COW。报告应明确：这是对“COW 权限状态机出错后果”的模型化演示，不是对真实漏洞的等价复现。

### 3.6 分支任务：双重 GDB 观察 `ecall` 与 `sret`

**负责人：宋秋实。**

调试链路按指导书执行：

1. `make debug` 启动 ucore 的 GDB 会话；
2. 在用户程序符号未加载时，先 `add-symbol-file obj/__user_exit.out`；
3. 在 `user/libs/syscall.c` 的系统调用封装处下断点，`si` 单步到 `ecall`；
4. 对 QEMU 进程另开 GDB，`Ctrl-C` 中断后在与 `ecall` 相关的 TCG/异常处理路径下断点；
5. 继续 ucore，观察从 U 态进入 S 态时 `pc`、`sepc`、`scause`、`sstatus`、`sscratch` 的变化；
6. 在系统调用返回前停在 `sret`，重复上述过程观察 S 态回 U 态；
7. 保存 GDB 命令、原始输出、QEMU 版本和源码函数名，报告中只写实际观察到的内容。

QEMU 侧要结合源码说明：`ecall` 在 TCG 中被翻译为异常 helper，最终进入 RISC-V 的异常/中断处理路径，设置 `sepc`、`scause` 并切换到 S 态；`sret` 则根据 `sstatus.SPP` 选择返回特权级，根据 `sstatus.SPIE` 恢复中断使能，并把 `sepc` 装回 `pc`。具体函数名要以本机 QEMU 源码为准，不能把其他版本的函数名硬套过来。TCG Translation 的意义是把 guest 指令翻译成宿主可执行的中间代码，`ecall/sret` 不是“被模拟器直接执行的一条硬件指令”，而是被翻译成 helper 调用和 CPU 状态更新。

## 7. 主要风险与排查顺序

| 风险 | 典型现象 | 首要排查 | 负责人 |
|---|---|---|---|
| `RESTORE_ALL` 仍按纯内核写法 | 系统调用返回后用户程序页故障或跑飞 | 检查 `sscratch`、`sp` 恢复顺序和 `sstatus` | 殷佳仪 |
| `epc` 重复前移 | `ecall` 返回后跳过指令或重复系统调用 | 确认只在 `CAUSE_USER_ECALL` 分支加 4 | 殷佳仪 |
| `kernel_execve` 直接返回 | 打印 `ret = 0`，但用户程序没有运行 | 确认执行流跳到 `__trapret`，`sp` 指向当前 `tf` | 殷佳仪 |
| 用户指针未检查 | 内核态页故障、非法地址 panic | 检查 `user_mem_check()` 的地址、长度、写权限 | 殷佳仪/兰雨杉 |
| `mm` 引用计数错误 | `exec`/`exit` 后释放仍在使用中的页表 | 检查 `mm_count_inc/dec` 与 `satp` 切换顺序 | 宋秋实 |
| 子进程 `a0` 未清零 | 子进程从 `fork()` 返回父进程 PID | 检查 `copy_thread()` 的 `tf->gpr.a0 = 0` | 宋秋实 |
| 僵尸未回收 | `init_main` 卡住或 `nr_process != 2` | 检查 `do_exit()` 唤醒与 `do_wait()` 扫描 | 兰雨杉 |
| COW 只改权限不复制 | 父子写入互相可见 | 检查页故障路径是否分配新页并复制 | 兰雨杉 |
| COW 后 TLB 未刷新 | 第一次写成功，第二次仍读旧页 | 检查 `tlb_invalidate()`/`flush_tlb()` | 兰雨杉/宋秋实 |
| 旧参考代码字段不匹配 | 编译错误或运行时结构错位 | 以本组基线结构为准，禁止整文件替换 | 全组 |

排查顺序固定为“先确认基线能启动，再确认用户态能进入，再确认系统调用返回值，最后才查 fork/exit/COW”。不要在启动链未稳定时直接调 COW，否则会把不同层的问题混在一起。
